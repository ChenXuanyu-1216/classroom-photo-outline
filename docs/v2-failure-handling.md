# V2 异常记录、处理方式与已知限制

> 2026-11-02 更新：网页后台作业现会保存独立的终态证据快照，恢复后可查询原失败页快照。详见 [EXP05 网页效果评价](exp05-web-evaluation.md)。下文关于“最新页错误清空”的描述仍适用于 page 表；“没有逐次网络重试事件”的限制仍保留。删除任务会删除关联快照，须先导出。

日期：2026-10-25。范围：既有 MVP F1–F9 核心闭环、N3 异常处理与 N7 可追溯记录；冻结的 MVP/PRD 不修改。本页记录当前实现和可复现证据，不把计划项写成已实现能力。

## 当前记录在哪里

| 记录位置 | 当前保存内容 | 读取/使用方式 |
| --- | --- | --- |
| SQLite `task_job` | 操作、状态、创建/开始/结束时间、结果、终态 `error={code,message,retryable}` | `GET /api/tasks/{id}/jobs/{job_id}`；任务查询返回 active_job/last_job。时间字段目前只在数据库，作业查询未直接返回 |
| SQLite `page` | 页号、失败标记、最后一次 `error_code/error_msg/error_retryable` | `GET /api/tasks/{id}/pages`，定位具体失败页 |
| 后端连接日志 | 识别/归组/拓展阶段、直连或环境代理、异常类型链、系统错误码 | 读取服务启动终端或自行重定向的日志；当前代码未配置专用滚动日志文件 |
| 成功识别 `_meta` | 模型、请求 ID、用量、耗时、尝试数、输入哈希与提示词版本 | 数据库识别快照；这是成功结果元数据，不是完整失败尝试账本 |
| 验证报告/人工台账 | 用例、输入、异常类别、处置、恢复结果与证据位置 | 按 [EXP05 输入与执行说明](exp05-test-inputs.md) 保存，使用 [问题记录模板](../evaluation/classroom-photos/templates/v2-issue-record.template.json) |

记录 API 不返回密钥、原始图片、服务商错误正文或底层异常原文。完整课件与原始响应即使为调试保存，也只应放在本地忽略目录，不直接加入公共台账。

## “完整自动审计”是什么意思

它指系统自动、按顺序保留每次调用和重试的事件历史，包括开始/结束时间、阶段、输入引用、错误类别、采取的处理动作和恢复结果；一次重试成功之后，之前的失败仍可追溯。它不是把所有请求正文或密钥写进日志。

例如“第一次超时→等待 0.5 秒→第二次成功→用户之后手动重试/确认”应分别留下可关联事件，而不能只剩最终 success。当前 V2 的作业终态和最新页错误不是这样的完整事件历史，本轮错误码修复也没有新增该审计系统。

## 模块职责与分类规则

| 模块 | 唯一职责边界 |
| --- | --- |
| `model_response_parser.py` | 纯 JSON/completion 解码和 schema 校验，抛中性异常类别；不依赖 HTTP、FastAPI、数据库或配置 |
| `model_output.py` | 定义识别、归组、拓展的数据模型和业务结构约束，不再解析 HTTP 响应 |
| `errors.py:model_response_error` | 将中性解析类别映射为公开错误码、安全文案与手动重试属性；不解析正文 |
| 三个模型适配器 | 组织本阶段请求、执行网络策略，调用共享解析器和错误映射；另行检查业务语义 |
| `pipeline.py` / `task_jobs.py` | 记录页/任务/作业状态，保留旧稿与恢复入口；不增加空字符串或 JSON 格式猜测 |

HTTP body 为零字节或仅空白，统一为 `MODEL_EMPTY_RESPONSE`；有效且正常结束的 completion，其 content 为空字符串或仅空白，统一为 `MODEL_EMPTY_CONTENT`。两者均可手动重试，不自动增加网络请求。

缺少 content、null/错误类型、空 choices、非空坏 JSON、非法 UTF-8、schema 不符、拒答或截断继续归入格式/协议异常。识别外层保留 `RECOGNITION_FAILED`，页级原因为 `MODEL_OUTPUT_INVALID`；归组和拓展分别保留 `CLUSTERING_FAILED` / `KNOWLEDGE_EXPANSION_FAILED`。超过响应大小上限优先判为格式/协议异常，即使内容全为空白也不绕过大小限制。

## 异常与处理矩阵

“允许手动重试”不等于“当前会自动重试”。下表的请求次数是本轮离线注入设置 `max_retry=1` 的观测值，调用对象均为 HTTP mock。

| 类型与编号 | 可复现输入/触发 | 页级或阶段错误 | 当前处理方式 | 本轮证据 |
| --- | --- | --- | --- | --- |
| E01 超时 | 识别持续抛 `ReadTimeout` | `MODEL_TIMEOUT`，页可重试 | 首次失败后退避，最多再试一次；用尽后记录失败，由用户检查网络并显式重试；不生成假结果 | 2 次模拟请求，页面失败、任务失败、无大纲 |
| E02 调用/连接失败 | 识别持续抛 `ConnectError` | 页 `MODEL_CONNECTION_FAILED`；识别直接调用兼容外层 `RECOGNITION_FAILED` | 有限退避后失败；日志记录阶段/连接方式/异常链；不静默改代理或模型 | 2 次模拟请求，具体页错误可读取 |
| E03 HTTP 空响应体 | HTTP 200，body 为零字节或仅空白 | `MODEL_EMPTY_RESPONSE` | 共享解析器判为空响应；不自动再付费，允许手动重新识别 | 1 次模拟请求，不能显示成功 |
| E04 模型空文本 | completion 正常结束但 `message.content=""` 或仅空白 | `MODEL_EMPTY_CONTENT` | 共享解析器判为空正文；不自动修补或补写内容 | 1 次模拟请求，不能显示成功 |
| E05 格式异常 | 正常 completion 中返回半截 JSON：`{"title":` | 页 `MODEL_OUTPUT_INVALID` | 拒绝无效/截断/缺字段结果，保留错误；归组/拓展校验失败分别使用 `CLUSTERING_FAILED` / `KNOWLEDGE_EXPANSION_FAILED`，已有大纲保留 | 1 次模拟请求；格式问题不触发网络自动重试 |
| E06 结构合法但无内容 | 标题、置信度等字段合法，`points=[]`，且没有 relations/flows | 页 `IMAGE_UNREADABLE`，页不可直接重试 | 按没有可用识别内容失败，提示换清晰图片；不把空大纲当成功 | 1 次模拟请求，页置信度归零且 failed_flag=true |
| E07 手动恢复 | 第一次 recognize 超时，修复后对同页显式重试 | 成功后页错误清空；旧作业仍为 failed | 新作业保存成功结果，旧作业保留终态；恢复前需要另外快照具体页错误 | 旧失败 2 次＋新成功 1 次模拟请求；旧作业未被改成成功 |

初轮新增 [test_exp05_failure_records.py](../lecture-syllabus-generator/backend/tests/test_exp05_failure_records.py) 核验 E01–E07：7 passed。错误分类修复后，更新 E03/E04 的公开错误码，连同解析器与三适配器传播/旧稿保护共 **71 项定向检查通过**。测试通过正常上传、异步提交、消费者执行、作业查询和页查询验证落库；使用临时 SQLite 和模拟 HTTP，没有真实模型调用。最终回归见 分类修复记录（历史资料未随源码分发）。

另有已存在的离线覆盖：HTTP 429/503 后恢复、过长 `Retry-After` 停止本轮自动重试、401/402 不自动重试、坏图付费前拒绝、归组 ID 错误、空拓展/伪造来源拒绝，以及失败保留旧稿。对应源码见 `test_v2_model_reliability.py`、`test_deepseek.py`、`test_ai_core_flow.py`、`test_knowledge_expansion.py`、`test_task_jobs.py`，历史验证见 V2 专项记录（历史资料未随源码分发）。

## 记录和处置顺序

1. 在恢复、重新识别或删除之前，保存任务状态、作业查询和页级查询 JSON。对外仅保留脱敏输入编号与哈希，不抄入密钥、课件正文或绝对源路径。
2. 按模板填写 run_id、case_id、job_id、task_id、页号、实际错误码、现象类别、时间、尝试次数、输入清单版本与证据路径。不能从错误码推断出的字段保持 null。
3. 填写处理方式：有限自动重试、检查直连/代理、修正密钥/余额、换图、手动重试或保留旧稿；标明自动处理还是人工操作。
4. 保存恢复后的新作业 ID、页状态和输出；记录为 recovered / failed / pending，不覆盖原失败记录。只看到提示正确不能证明服务已经恢复。
5. 真实、模拟和未执行记录分开；失败或未完成尝试不能从统计分母消失。HTTP 200 不代表结构/内容有效，202 只代表请求已接受。

## 必须说明的当前限制

1. **尚无完整的自动问题台账。** 作业保存的是终态；网络内部每次重试没有单独的持久事件行。成功页错误会被清空，删除任务会连同作业删除。因此 EXP05 应在操作前后导出快照或填写独立台账，不能承诺事后还原全部失败。
2. **语义空结果仍有边界。** 空 HTTP body、空模型文本和格式错误现已分开；“结构合法但无知识点”与不可读页面仍由识别业务层共用 `IMAGE_UNREADABLE`。它不能证明模型准确判定了图片质量，本轮没有扩大为新的语义诊断能力。
3. **作业错误可能是汇总错误。** 所有页均失败时，pipeline 作业可为 `PIPELINE_ERROR`，只有页级数据保留 `MODEL_TIMEOUT` 等具体原因。作业的 retryable 不能代替逐页判断，尤其不能据此重试不可读图片。
4. **失败记录的诊断字段有限。** 失败路径没有统一保存模型 request_id、usage、HTTP 状态、阶段和耗时；有些信息只在文案/连接日志或验证报告。缺失要记 null，不能借用上一次成功元数据。
5. **超时配置不等于整个任务截止时间。** 默认模型超时 60 秒是 HTTP 客户端的超时配置，不是整条业务的总耗时保证；多页、重试、归组、拓展和图示复核会增加总耗时。浏览器轮询约十分钟的等待窗口也不是后台任务取消或硬截止；轮询还包含请求耗时。
6. **队列只有单机能力。** SQLite、一个后台消费者、最多 20 个等待作业；无分布式调度、取消、优先级或多用户隔离。运行中断只标记失败并等待手动重试，不保证远端请求恰好执行一次。
7. **输入与输出能力有限。** 真实识别仅 JPG/JPEG/PNG；PDF/PPTX 先转图片。正文来源、AI 标签和两级大纲继续保留；低清、遮挡、复杂图、公式和代码仍需人工核对。模拟成功不能证明真实识别准确。
8. **真实证据有限。** 已有一轮 V2 合成图任务通过，3 次真实请求首次 200、约 6.69 秒；不等于 EXP05 已完成，也不证明多课程质量、长期成功率或总体性能达标。原三元账本当前保守预留 2.80 元，剩余 0.20 元，不足再次运行至少预留 0.30 元的完整合成图验证。

EXP05 的准备输入、执行顺序与待补项见 [EXP05 测试输入与交接](exp05-test-inputs.md)。初轮补测试与验收资料，后续按用户要求修正解析分类并拆分职责；均未新增产品业务能力、运行依赖或付费调用。
