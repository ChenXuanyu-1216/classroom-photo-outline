# W8 EXP05 网页效果评价

日期：2026-11-02。网页为主要开发与验证入口，小程序继续使用现有接口。本页说明已开发的能力；不代表真实课件与用户验证已经通过。

## 网页操作

1. 按正常流程登录、上传照片和生成大纲。后台作业完成、部分完成或失败时自动保留一份证据快照。
2. 在大纲页点击“效果评价与证据”，或在处理页点击“查看效果与错误证据”。来源栏“打开原图对照与评价”会带上选中的页码。
3. 选择要评价的轮次。检查其时间、成功/失败状态、实际识别元数据和保存稿。失败轮次保留的旧稿明确标记，不能当成本轮新输出。旧任务没有历史快照时，可“保留当前状态”；不会调用模型，也无法补回历史首次输出。
4. 对照原图记录人工期望、实际输出和证据。选择页面、单个模块或整个任务，填写评审者代号及自评/独立复核/裁决。单模块必须从“本轮输出模块”选择，不能自由填写名称；服务端同时校验快照、模块标识与标题。内容计数可全部留空；填写时完整填写六项，并在文字中列出单元对应关系。不要把关键词出现次数当准确率。
5. 单个模块可填写结构与复习可用性 0–4 分。两项均至少 3 且该记录没有关键错误，才满足本协议的单模块口径；未评分、未绑定真实模块、无保存稿或本轮保留旧稿不生成模块通过判断。空模块不能因高分通过。历史无模块绑定记录保留原分数，显示未绑定，不自动补造通过结论。
6. 对错误填写类别、正确内容与原图位置、实际片段、影响；多项错误可追加记录。在“核心流程与用户验证（一）”填写实际执行状态和真实用户反馈，未执行保持未执行。
7. 保存为追加记录。保存请求期间继续编辑的内容仍会标记尚未保存，须再次提交；刷新失败后仍保留原快照草稿。修订时新增一份并说明理由；切换快照时未保存的评价会提示确认。分别导出证据 JSON 和评价 Markdown 报告。报告保留各评审者的原始记录，不自动拼成总体准确率或整体通过结论。

## 保存的证据

- 输入页码与原图 SHA-256，页级错误、识别正文与结构化结果、已保存的安全模型元数据。
- 当轮作业状态、错误、起止时间及墙钟耗时；当时保存的大纲、版本与旧稿标记。
- 取证时磁盘上的应用代码和提示词哈希，以及不含密钥的识别/归组/拓展配置。
- 不可变证据 JSON 的 SHA-256；每份追加人工记录的 ID、范围、评审方式、时间、原始计数、错误与流程状态。

快照保存在 `evaluation_snapshot`，人工记录保存在 `evaluation_review`，启动时自动创建新表。它们沿用任务归属鉴权；其他用户无法查看、评分或导出。删除任务会级联删除这些记录，删除确认中已提示先导出。下载文件包含课程内容与人工备注，按课件许可保存；原图不包含在 JSON 中，需另行留存。

## 可复核口径

忠实度 = 有本页证据支持的输出事实单元 / 全部输出事实单元。

覆盖率 = 正确恢复的不同期望单元 / 全部可辨认期望单元。

来源正确率 = 正文及来源均正确的输出条目 / 全部来源条目。

零分母保持 null，网页显示“未评分／无比率”；无比率不等于正确弃答或 N/A 判定。空输出、执行失败与不可读区域的具体评分仍按[完整人工协议](classroom-photo-rubric.md)人工登记，不能只凭百分比下结论。正式评价应先独立冻结期望，并保留分歧裁决；网页记录支持取证，不自动证明这些程序已履行。

## 本轮必要检查

只运行新能力及直接受影响的网页、后台队列检查，不恢复历史全量、重复付费或长期采样。验证错误恢复后旧证据不变、旧稿不会被判为本轮通过、未评分不变成零分或通过、计数/错误必填约束、归属隔离与删除一致性；另实际打开网页核对原图、保存、重开和下载。

## 能力边界与正式 EXP05 剩余工作

- 自动快照覆盖网页采用的异步后台作业；同步 API 及老任务仅支持手动当前状态取证，不补写历史。
- 快照记录终态，不是完整的逐次网络重试审计。中断恢复时只能保存当时仍存在的信息，失败路径缺少的 request_id/usage 保持缺失。
- 代码/提示词哈希来自取证时磁盘，不证明历史运行加载了这些文件。识别实际元数据与配置分开；复用的识别、旧缓存和人工修改须结合快照种类判断。
- 原图从任务存储按鉴权读取，能取得输入哈希时在浏览器核对一致性；原图丢失或损坏时明确显示不能用于评分。
- 原多模态识图、模型归组和 AI 知识拓展继续使用。本轮没有新增 RAG、工具调用或智能体，避免在效果评价前扩展不必要的功能。
- 正式新课件批次、人工金标准、独立评分和真实用户访谈仍需实际完成。此次没有调用付费模型、扩额或改变日常费用设置。3–5 页试用不能替代基线 VH1 的多课程要求。
